## 1. 概述

### 1.1 需求来源
用户需求：开发一个双角色（坦克 + 遥控器）Demo，通过 WiFi 实现视频流、控制指令和语音数据的实时传输，展示 ESP32-S3 平台的多模块协同能力。

### 1.2 Demo 定位
- **编号**: EX-035
- **名称**: rc_tank_demo（遥控坦克）
- **复杂度**: 中高（跨模块集成：摄像头、电机、音频、网络、触摸屏）
- **参考 Demo**: 
  - EX-002 (motor_demo): 电机控制
  - EX-018 (camera_display_demo): 摄像头采集
  - EX-024 (xiaozhi_companion_robot_demo): 网络、音频、状态机
  - EX-009 (audio_opus_demo): Opus 编解码

### 1.3 核心特性
单一代码库通过宏定义区分两种角色：
- **坦克角色**：接收控制指令驱动电机，采集摄像头画面通过 WiFi 发送，接收并播放语音
- **遥控器角色**：显示坦克视频流，通过触摸屏悬浮摇杆发送控制指令，SW3 按键录音并发送

## 2. 功能需求

### 2.1 角色定义与硬件配置

#### REQ-035-001: 坦克角色硬件组成

**描述**: 坦克由以下板卡组成：
- A0 核心板（主控 ESP32-S3 + WiFi + 音频输出链路 + 电池管理）
- C0 扩展板（40pin 转接桥）
- D0 电机控制板（PT2466 × 2，双路直流电机）

**硬件可行性**: EX-027 已验证摄像头 + LCD + 电机三者同时工作（GPIO 无冲突，摄像头经 CN8/C0，LCD 经 CN3）

**验收标准**:
- 宏定义 `CONFIG_RC_TANK_ROLE_TANK=y` 时编译出坦克固件
- 初始化日志显示"Role: TANK"
- 检测到 D0（ADC≈1.45V）和 E0 板卡存在
- 屏幕成功初始化并显示坦克静态像素图

- 屏幕板（ST7789V3 LCD 320×240 + CST836U 触摸）
- B0 MIC 板（双 MIC 采集，SW3 录音触发）

- LCD 和触摸成功初始化
- SW3 按键（GPIO8 ADC）响应正常

### 2.2 通讯链路

#### REQ-035-003: WiFi 点对点连接
**优先级**: P0  

**原始需求摘录**（来源：用户，记录时间：2026-08-25，适用对象：RC Tank Demo 双端网络与状态显示）：

> 从你当前的分析看，可能是坦克的wifi断连后没有重新处理连接任务，这个角度也看看，我需要的正式需求是，两者上电自动连接，若有断连两端自动处理重连，同时遥控器的左上角要有个wifi连接状态的标志与坦克右上角的连接状态保持一致

**描述**: 
- 坦克作为 SoftAP（SSID: `RC_TANK_<MAC_SUFFIX>`，密码: `12345678`）
- 两端以任意先后顺序上电时，遥控器作为 STA 自动扫描并连接坦克热点；热点暂时不存在时保持本机运行并持续扫描，不得以整机重启代替等待连接
- 默认绑定关系通过固定 SSID 前缀识别
- 已建立的连接断开时，两端都必须进入断连状态并自动处理恢复：坦克保持 SoftAP、立即执行失联安全停车并等待遥控器重新接入；遥控器执行每轮最多 3 次、间隔 5 秒的重连，失败后返回扫描热点并继续循环，直至重新连接或设备断电
- 重连成功后双方恢复网络通道，但坦克继续保持停止状态，必须收到新的有效摇杆操作才允许运动；不得重复创建 socket 或视频/控制任务
- Remote 左上角和 Tank 右上角分别显示本机观测到的同一连接状态：未连接为红色，已连接为绿色；上电等待、断连和重连成功时均随网络状态更新

**验收标准**:
- 坦克上电后 5 秒内 SoftAP 启动
- 遥控器扫描到坦克热点并自动连接，15 秒内完成握手
- 连接成功后双方 LED 指示（绿灯常亮）
- 只给Remote上电且Tank热点不存在时，Remote至少连续运行60秒、重复扫描且无软件复位、Panic、WDT或卡死；随后给Tank上电，无需人工重启Remote即可自动连接
- 已连接后人为关闭或复位Tank，Remote立即显示红色并持续执行重连/重扫；Tank重新出现后，两端无需人工复位即可恢复连接
- Tank检测STA断开后立即进入安全停车并把右上角图标置红；Remote失去IP/连接后把左上角图标置红；重连成功后两端图标均置绿，稳定连接期间不得出现相反状态
- 重连后控制、视频通道恢复且各任务只有一个实例；坦克保持停车，直至新的有效摇杆操作到达

#### REQ-035-004: 数据通道划分
**优先级**: P0  
**描述**: 三条独立数据流：
1. **控制流**（遥控器 → 坦克）: UDP 端口 8001，低延迟优先
2. **视频流**（坦克 → 遥控器）: UDP 端口 8002，8 字节帧头（magic 0xAA55 + seq + length），实时优先
3. **语音流**（遥控器 → 坦克）: TCP 端口 8003，完整性优先

**验收标准**:
- 各通道独立收发，互不阻塞
- 控制流端到端延迟 < 50ms（WiFi 正常时）
- 视频流 UDP 传输，丢帧不阻塞，发送失败直接丢弃
- 语音流支持分片重组（单段最大 64KB）

### 2.3 控制指令（遥控器 → 坦克）

#### REQ-035-005: 悬浮摇杆控制
**优先级**: P0  
**描述**: 
- 遥控器屏幕显示半透明悬浮圆形摇杆，中心 `(108,136)`，底座半径 `72px`、摇杆头半径 `34px`，位于 320×240 横屏左下区域
- 初次触摸捕获半径为 `108px`；捕获后允许手指拖出初始区域，摇杆偏移按真实圆形半径和最大行程 `62px` 限幅，松手立即回中
- 横屏坐标中“屏幕向上”为 `0°` 前进、向右为 `+90°`、向左为 `-90°`、正下方统一为 `+180°` 后退；角度按 `atan2(dx,-dy)` 的最近整数度表达，范围包含 `-180..+180`
- 距中心 `<10px`、未触摸或未捕获时输出 STOP，角度和力度均为 `0`；半径 `10..62px` 时输出 DRIVE，逻辑力度按 `1 + round((radius-10)*99/52)` 线性映射到 `1..100`
- 角度或力度半点采用远离 `0` 取整；协议力度始终为硬件无关逻辑量，Remote不得感知电机死区、PWM曲线或启动占空比
- 控制任务每 `20ms` 检查一次；`mode/angle/magnitude` 任一变化时立即发送。DRIVE保持不变时是否继续每`100ms`保活不受本次空闲变更直接否定，但仍需与Tank `300ms`超时安全契约共同验收
- **2026-08-27正式变更**：遥控器在摇杆完全无操作时不得持续向Tank发送控制数据；该要求替代“无操作期间每100ms持续发送STOP”的旧口径
- Remote由DRIVE进入STOP（含松手、回中或进入摇杆死区）时立即发送一次STOP；仅发送成功后提交发送状态并递增序号，失败时保持同一序号按20ms控制周期重试
- STOP成功后，在当前仍为STOP且连接世代未改变期间保持静默；断连时停止发送，重连且摇杆仍为空闲/STOP时重新发送一次STOP，成功后再次静默

**验收标准**:
- 摇杆触摸响应延迟 < 30ms
- 纯C覆盖未触摸、`9/10/62/63px`边界、四个轴向、四个象限、圆形限幅、角度和力度舍入
- 人工沿任意方向连续拖动时，Tank接收的角度和力度连续变化；纯水平 `±90°` 保留原地转向语义
- 控制包为固定 `14` 字节V1大端格式：`magic=0x5243`、`version=1`、`mode`、`angle_deg`、`magnitude_pct`、`reserved=0`、`seq`、`sender_time_ms`
- STOP发送端固定编码 `angle_deg=0,magnitude_pct=0`；DRIVE仅允许角度 `-180..180`、力度 `1..100`
- 摇杆复位后必须立即发送一次STOP使Tank停车；发送失败保持同一序号按20ms控制周期重试，成功后在当前连接世代内保持空闲静默
- 持续按住同一非STOP方向500ms时，控制包间隔均不超过100ms，坦克不得因300ms接收超时自行停车；完全无操作时不得用周期STOP维持该间隔

#### REQ-035-006: 坦克电机执行
**优先级**: P0  
**描述**: 
- 坦克接收V1控制包，驱动左、右两台PT2466履带电机；协议不兼容旧7字节五态控制包
- 只有长度、魔数、版本、保留位、模式、参数域和序号均有效的新包才能更新目标并刷新300ms有效包时间；UDP控制通道不返回响应或错误码，非法包只做限频本地诊断
- 首个有效包直接建立序号基线；后续仅当 `(uint16_t)(new_seq-last_seq)` 位于 `1..32767` 时接受，`0`为重复，`32768..65535`为旧包，`65535→0`允许自然回绕
- `0..90°`满力度右转节点依次为 `(0,100,100)`、`(15,100,65)`、`(30,100,30)`、`(45,100,-10)`、`(60,100,-80)`、`(75,100,-95)`、`(90,100,-100)`；节点间线性插值，负角交换左右，后退半区按取反并交换生成
- 先计算满力度左右履带逻辑速度，再乘 `magnitude_pct/100` 并按半点远离0取整；逻辑输出限制在 `-100..100`
- Tank端共享基础PWM曲线为逻辑速度 `0→0%`、`1→50%`、`100→100%`，节点间线性插值；左前、左后、右前、右后四个方向校准槽分别保留占空比偏移、启动占空比和启动助推时长
- 四个方向槽首版均使用偏移 `0`、启动占空比 `60%`、助推 `60ms`；偏移合法域为 `-20..20` 个百分点，启动占空比为 `1..100%`，助推为 `20..200ms` 且必须为 `20ms` 整数倍。配置非法时初始化失败并保持停车
- 从完全停止进入非零输出时，目标占空比低于启动占空比则先输出启动占空比并在助推结束后回落最新目标；目标不低于启动占空比则直接输出目标，不增加固定助推
- 已运行且同方向时，每20ms最多增加20逻辑点、减少25逻辑点；单履带正反换向时立即归零、保持40ms死区，再从零按每20ms最多20逻辑点进入反向
- 左右履带独立执行斜坡、助推和换向；最新目标覆盖旧目标，不排队、不使用低通滤波

**验收标准**:
- 收到有效新指令后 `20ms` 内开始更新电机输出；重复、旧包和非法包不得改变输出目标
- 纯C精确覆盖协议字节序、非法字段、序号回绕、角度节点/插值/对称、力度缩放、PWM曲线、四方向配置、启动助推、快速斜坡、40ms换向死区及立即STOP
- 满力度 `±90°` 的逻辑履带速度分别为 `(+100,-100)`、`(-100,+100)`；典型单履带 `+100→-100` 在40ms换向死区后以每20ms最多20逻辑点进入反向，约 `120..140ms` 到达目标
- 实机确认四个方向槽默认偏移`0`、启动占空比`60%`、助推`60ms`可使前进、后退和掉头正常启动；按最终混控曲线连续转向时方向和手感符合人工验收

#### REQ-035-006B: 坦克屏幕显示
**优先级**: P1  
**描述**: 
- 坦克屏幕（ST7789V3 320×240）主体显示一张坦克静态像素图
- 屏幕角落显示 WiFi 连接状态（如右上角图标：已连接=绿色，未连接=灰色/红色）
- 屏幕角落显示电池电量（如左上角：电压或百分比）
- 屏幕内容为状态展示用途，不显示视频流（视频流发往遥控器）

**验收标准**:
- 上电后屏幕点亮并显示坦克像素图
- WiFi 连接/断开时角标状态实时更新，未连接为红色、已连接为绿色
- 电量数字和百分号必须使用正确 5x7 字形，`75%` 等显示可辨认；红、绿、蓝、白按 LCD 实际 RGB565/BGR 字节契约显示正确
- 电量显示每 5 秒刷新一次
- 屏幕刷新不阻塞电机控制和视频发送任务

#### REQ-035-007: 失联安全停车
**优先级**: P0  
**描述**: 
- 坦克超过 300ms 未收到有效新控制包，自动执行停车；非法、重复或旧包不得刷新超时
- WiFi 断连事件触发立即停车
- 2026-08-27正式变更要求摇杆完全无操作时不得持续发包，替代此前“每100ms发送心跳停止包”的旧口径；进入STOP发送一次，失败保持同序号重试，成功后静默，重连空闲重新发送一次STOP
- STOP、WiFi断连和有效包超时均绕过速度斜坡立即输出 `0%`，取消助推/换向状态并清除序号基线

**验收标准**:
- 模拟遥控器断电，坦克 350ms 内停车
- 模拟 WiFi 干扰断连，坦克立即停车并 LED 指示（红灯闪烁）
- 恢复连接后坦克保持停止状态，需重新操作摇杆
- 连续发送非法、重复或旧包时，坦克仍须在最后一个有效新包后的350ms内停车

### 2.4 视频流（坦克 → 遥控器）

#### REQ-035-008: 摄像头采集与编码
**优先级**: P0  
**描述**: 
- 坦克采集 SP0A39 摄像头（640×480 VYUY），缩放至 240×180
- SCCB/I2C 只使用板级配置地址 `0x21`；总线扫描只用于诊断，不得把触摸控制器 `0x15` 或其他 ACK 地址选作摄像头
- 摄像头 ID 必须读取为 `0x0A39` 才允许继续写初始化表和创建/启动 DVP；地址无响应或 ID 不匹配时明确失败，不得以空控制器继续启动视频
- 硬件/软件 JPEG 编码，质量因子 Q=60，目标帧率 10-15fps
- 编码后帧大小目标：平均 8-12KB，峰值 < 20KB

**验收标准**:
- 摄像头初始化成功，MCLK=20MHz
- `0x15` 与 `0x21` 同时 ACK 时仍选择 `0x21`，日志显示 `SP0A39 chip ID: 0x0A39`
- ID 为 `0x0000` 或摄像头初始化失败时不得调用空 DVP 控制器
- JPEG 编码器工作正常（优先使用 ESP32-S3 硬件加速）
- 实测帧率稳定在 10±2fps
- 单帧编码时间 < 80ms

#### REQ-035-009: 视频流传输
**优先级**: P0  
**描述**: 
- 坦克通过 UDP 端口 8002 持续发送 JPEG 帧；每个 datagram 的视频载荷不超过 1200B，避免依赖 IP 层大报文分片重组
- 每片沿用 8 字节头：`magic=0xAA55`、`length=本片载荷长度`、`seq=帧序号`、`reserved高字节=总片数`、`reserved低字节=片序号`
- 遥控器只在同一 `seq` 的全部分片到齐后软解码并显示；缺片帧由后续新帧替换，不得阻塞控制通道

**验收标准**:
- WiFi 带宽充足时帧率达到 10fps 以上
- 遥控器显示延迟 < 200ms（采集→显示端到端）
- 丢帧时不花屏，跳过残缺帧显示上一帧
- 长时间运行（10 分钟）无内存泄漏

#### REQ-035-010: 遥控器视频显示与状态叠加
**优先级**: P0  
**描述**: 
- 视频流保持 240×180 原尺寸，贴屏幕右上角 `(80,0)` 显示，不放大到全屏
- LVGL canvas 或直接 framebuffer 渲染
- 在 320×240 画布上叠加半透明悬浮摇杆和状态信息（帧率、信号强度、电池电量）
- 电量显示在屏幕角落（如左上角：电压或百分比，每 5 秒刷新）
- 摇杆控件由遥控器显示合成任务独立刷新；首个视频帧到达前、视频初始化失败、无视频或视频中途停流时仍必须显示并响应触摸

**验收标准**:
- 视频显示流畅，无明显撕裂
- 帧率显示在屏幕右上角（白色半透明文字）
- 电量显示在屏幕左上角（半透明文字 + 电池图标）
- 摇杆和视频层级正确（摇杆在上）
- 零视频帧时可显示黑色/无信号底图，但摇杆必须可见；视频停流期间移动摇杆仍触发重绘，不等待新视频帧

### 2.5 语音传输（遥控器 → 坦克）

#### REQ-035-011: 遥控器录音触发
**优先级**: P0  
**描述**: 
- SW3 按下（GPIO8 ADC < 3000）开始录音，松开（ADC > 3500）结束录音
- 录音采样率 16kHz，单声道，16bit PCM
- 录音时长限制：最短 0.5 秒，最长 10 秒
- 屏幕显示录音状态（红色圆点闪烁）

**验收标准**:
- SW3 按下响应延迟 < 50ms
- 录音数据无破音、爆音
- 录音时长显示实时更新
- 录音时摇杆控制不受影响（并发处理）

#### REQ-035-012: 语音编码与传输
**优先级**: P0  
**描述**: 
- 录音结束后立即使用 Opus 编码（复用 EX-009 方案）
- 编码参数：16kHz, mono, 60ms frame, bitrate=24kbps
- 编码完成后通过 TCP 端口 8003 一次性发送
- 传输格式：`{magic: 0xBB66, length: uint32_t, sample_rate: uint16_t, data: uint8_t[]}`

**验收标准**:
- 10 秒录音编码完成时间 < 1 秒
- 编码后数据压缩比 > 6:1（16kHz PCM → 24kbps Opus）
- 传输完成前屏幕显示"发送中..."
- 网络异常时提示用户并允许重发

#### REQ-035-012B: 电池电量检测（坦克与遥控器通用）
**优先级**: P1  
**描述**: 
- A0 核心板通过 `GPIO7 / BAT_ADC`（VBAT 分压）检测电池电压
- 坦克和遥控器均在屏幕角落显示电量
- 电压→百分比换算：需结合电池分压系数和实测阈值（充电芯片 ETA6002E8A，电池连接器 VBAT/NTC）
- 显示形式：电池图标 + 电压值或百分比

**验收标准**:
- ADC 读取稳定（多次采样平均，去抖）
- 电压换算合理（满电/低电阈值待电池资料实测标定）
- 显示每 5 秒刷新
- BAT_ADC 仅作模拟输入，不当数字 IO 使用（遵循 design.md 5.3 约束）

#### REQ-035-013: 坦克语音解码播放
**优先级**: P0  
**描述**: 
- 坦克接收完整语音包后 Opus 解码
- 通过 A0 核心板 ES8311 codec + 功放 + 喇叭播放
- 播放音量固定为 70%（`CONFIG_AUDIO_VOLUME=70`）
- 播放期间 LED 指示（蓝灯闪烁）

**验收标准**:
- 解码无失真，音质可辨识
- 播放延迟（接收完成→出声）< 500ms
- 播放完成后自动返回待机状态
- 多段语音排队播放，不丢弃

## 3. 非功能需求

### 3.1 性能指标

#### REQ-035-014: 实时性
- 控制指令端到端延迟 < 100ms（P95）
- 视频流端到端延迟 < 300ms（P95）
- 系统响应用户交互 < 50ms
- 视频性能调优必须先按采集、下采样、编码、UDP 分片发送/接收与重组、解码和 LCD 刷新分阶段计算理论吞吐与时延预算，再以同口径实测数据定位差距；不得把某次实测值直接当作理论最优值

#### REQ-035-015: 稳定性
- 连续运行 30 分钟无崩溃
- WiFi 断连重连成功率 > 90%
- 内存使用稳定（堆水位线波动 < 20KB）

#### REQ-035-016: 资源占用
- 坦克固件大小 < 2.5MB（留出 OTA 空间）
- 遥控器固件大小 < 2.5MB
- 运行时峰值堆占用 < 200KB（PSRAM 不限）

### 3.2 可维护性

#### REQ-035-017: 代码结构
- 单一代码库，宏定义区分角色（`CONFIG_RC_TANK_ROLE_TANK` / `REMOTE`）
- 模块化设计：网络层、控制层、视频层、音频层独立
- 每个模块提供统一初始化接口 `xxx_init()` 和去初始化接口 `xxx_deinit()`

#### REQ-035-018: 调试支持
- 上电后 10 秒启动延迟（沿用 XCR-028，便于串口日志抓取）
- 关键事件打印日志（连接、断连、帧率、丢包率）
- 正式固件只保留低频采集/发送/显示帧率及必要错误摘要，不保留逐帧CRC、自解码、窗口矩阵、内部时延探针或高频分片日志
- 专项诊断不得作为正式启动流程或正式构建选项；需要重新定位问题时，以独立、可回退的临时修改实施并在验证后移除

### 3.3 用户体验

#### REQ-035-019: 启动流程
- 坦克上电后自动启动 SoftAP，RGB LED 绿灯慢闪等待连接
- 遥控器上电后自动扫描并连接，屏幕显示"连接中..."
- 连接成功后遥控器自动进入控制界面，坦克 LED 绿灯常亮

#### REQ-035-020: 异常提示
- WiFi 连接失败：遥控器屏幕显示"未找到坦克"并重试
- 视频流中断：遥控器显示"视频信号丢失"
- 坦克失联：遥控器屏幕红色边框闪烁

**GPIO 冲突核查结果**：摄像头 DVP、LCD SPI、电机 IN 无重叠，EX-027 已验证三者同时工作可行。

### 4.2 外设初始化顺序
1. IOEX (TPT29555A, I2C addr=0x22)
2. RGB LED 初始化并设置为红色（启动中）
3. WiFi 初始化
4. 角色特定外设：
   - 坦克：D0 检测 → 电机 GPIO → 摄像头 DVP → 音频输出
   - 遥控器：LCD/触摸 → SW3 ADC → 音频采集
5. 网络连接建立
6. 数据流任务启动

### 4.3 电源与功耗
- 坦克功耗：待机约 0.8W，电机运行约 3-5W（取决于负载）
- 遥控器功耗：屏幕常亮约 1.2W
- 推荐电源：5V/2A USB 供电（双设备均需独立供电）

## 5. 边界与约束

### 5.1 不包含的功能
- 不支持多坦克 / 多遥控器配对（1v1 固定绑定）
- 不支持坦克主动采集环境音回传（B0 保留但不启用）
- 不支持遥控器录制视频到 TF 卡
- 不支持 OTA 固件升级（后续扩展）
- 坦克屏幕不显示视频流（仅状态展示：WiFi 状态 + 坦克像素图 + 电量）
- 不实现完整电池充放电管理（仅电量显示；充放电策略沿用 A0 硬件默认）

### 5.2 已知限制
- WiFi 点对点有效距离约 10-15 米（室内无遮挡）
- 视频帧率受 WiFi 信号强度影响，弱信号时可能降至 5fps
- 语音传输为整段发送，最长 10 秒录音传输时间约 1-2 秒
- 摇杆仅支持单点触摸，不支持多指手势

### 5.3 依赖项
- ESP-IDF v5.5.4 或更高版本
- LVGL v8.x（屏幕 UI）
- Opus 编解码库（已在 EX-009 集成）
- JPEG 编解码库（ESP32-S3 硬件加速或 libjpeg-turbo）
