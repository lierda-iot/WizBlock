# 测试与验证证据

[中文](testing.md) | [English](testing.en.md)

## 证据层级

| 层级 | 证明范围 | 不能替代 |
| --- | --- | --- |
| 纯C/主机测试 | 状态、协议、边界、时序与可注入逻辑 | ESP-IDF目标构建、真实外设 |
| clean build | 当前镜像、依赖和目标工具链可生成固件 | 烧录、启动、功能行为 |
| flash/hash | 固件写入目标区域并校验 | 应用启动和外设正确性 |
| 启动日志 | 初始化、资源和错误出口可观察 | 完整交互与长期稳定性 |
| 功能实机 | 指定板卡/固件/环境下的可观察行为 | 未覆盖平台、边界或30分钟长稳 |

所有“已验证”必须指向当前源码版本的可靠证据。历史证据可保留，但要标历史；未运行不得写通过。

## 最小执行顺序

1. 运行受影响模块最小主机测试。
2. 重新完整镜像并执行目标 Example clean build。
3. 设备任务取得授权后确认端口，按成熟流程全片擦除、烧录和校验。
4. 观察启动错误和目标行为。
5. 高风险硬件再执行边界、错误注入和稳定性矩阵。

生成物、串口日志和设备标识不自动进入公开候选；公开证据应脱敏并保留最小必要摘要。
