# D0 电机板热插拔 ADC 干扰问题分析记录

记录时间：2026-07-08（持续更新；2026-07-24 闭环）

> 当前结论（2026-07-24）：原波动根因已由用户确认是检测脚没有固定电平、处于浮空状态；硬件上拉改动后波动已解决。Round 1~8 是旧硬件状态下的历史取证，其中尚未解释的测量矛盾不再作为当前根因调查入口。当前正式硬件为 C0 ADC 节点新增 20kΩ 上拉到3.3V、D0移除R12并保留R13=15kΩ下拉；核心板+C0实测3.3V，核心板+C0+D0实测1.45V。旧换算和Round 7临时GPIO释放流程已从正式源码移除，当前改用raw中值、ESP-IDF校准、饱和档/1.45V档分类和完整电机生命周期。正式固件已完成两轮D0插入/拔出实机回归，用户最终确认Demo无问题。

## 1. 现象描述

| 项目 | 内容 |
|------|------|
| 环境 | 核心板 + C0 扩展板 + D0 电机板，ESP32-S3，ESP-IDF v5.5.4 |
| ADC 配置 | GPIO1 = ADC1_CH0，11dB 衰减，oneshot 模式，5 次中值滤波 |
| 正常值 | 核心板+C0+D0 状态，ADC 读数 ~1913mV |
| 异常表现 | 任何电机 GPIO 配置为输出后，ADC 读数永久跌落至 ~574mV，不恢复 |
| 万用表对照 | 异常发生后，万用表实测 GPIO1 外部电压仍为 0.8V，未变化 |
| 影响 | 无法通过 ADC 识别 D0 板拔出（死锁） |

## 2. 硬件事实

- ADC 检测脚：GPIO1 = ADC1_CH0
- 电机引脚：IN1=GPIO5(ADC1_CH4), IN2=GPIO4(ADC1_CH3), IN3=GPIO37, IN4=GPIO45
- D0 板 ADC 分压网络：VDD33 → 110kΩ → ADC 节点 → 15kΩ → GND
- PT2466 H-bridge 驱动器：无 I2C/SPI，仅 IN/nSLEEP/nFAULT 引脚
- D0 板连接器 U5 (10pin)：IN1-IN4, V_SYS×2, GND×2, VDD, ADC
- 所有电机 GPIO（5/4/37/45）通过 C0 连接器物理连接到 D0 板 PT2466 IN 引脚

## 3. 验证记录（按时间顺序）

### Round 1：跳过 GPIO4(IN2)，仅配置 GPIO5/37/45 为 LEDC 输出

| 项目 | 内容 |
|------|------|
| 猜测 | GPIO4 = ADC1_CH3，可能是 ADC1 内部通道串扰导致 GPIO1 读数异常 |
| 操作 | LEDC 初始化跳过 GPIO4，仅配置 GPIO5/37/45，20kHz，duty=0 |
| GPIO 是否连接外部电路 | 是，GPIO5/37/45 通过 C0→D0 连接到 PT2466 |
| 结果 | ADC 从 1918→584mV 跌落 |
| 结论 | GPIO4 不是唯一触发源；但未排除 GPIO5(ADC1_CH4) 的影响 |

### Round 2：跳过 GPIO4+GPIO5，仅配置 GPIO37/45 为 LEDC 输出

| 项目 | 内容 |
|------|------|
| 猜测 | GPIO5 = ADC1_CH4，连同 GPIO4 一起跳过后，如果 ADC 恢复则确认是 ADC1 通道串扰 |
| 操作 | LEDC 仅配置 GPIO37/45，20kHz，duty=0 |
| GPIO 是否连接外部电路 | 是，GPIO37/45 通过 C0→D0 连接到 PT2466 |
| 结果 | ADC 从 1916→600mV 跌落 |
| 结论 | **排除 ADC1 内部通道串扰**——GPIO37/45 不属于 ADC1（ADC1 仅覆盖 GPIO1~10），但 ADC 仍跌落 |

### Round 3：D0 识别后完全不做任何 GPIO 操作

| 项目 | 内容 |
|------|------|
| 猜测 | 如果是 D0 板上电本身导致干扰（如 DCDC 启动、PT2466 浮空态），则不配置 GPIO 也应跌落 |
| 操作 | d0_on_insert() 内不做任何 GPIO/PWM 配置，仅打印日志 |
| GPIO 是否连接外部电路 | 无 GPIO 操作，无关 |
| 结果 | ADC 稳定保持 1912~1918mV，持续超过 2 分钟 |
| 结论 | **排除 D0 板上电特性干扰**——D0 板在位但不配置 GPIO 时 ADC 完全正常 |

### Round 4：改用 MCPWM（独立 PLL_F160M 时钟），4 路 GPIO5/4/37/45

| 项目 | 内容 |
|------|------|
| 猜测 | 实验 2 排除 ADC1 通道串扰后，怀疑 LEDC timer 共享 APB_CLK 干扰 ADC SAR；MCPWM 使用独立 PLL_F160M 时钟，如果不干扰则确认是 LEDC 时钟域问题 |
| 操作 | MCPWM 配置 4 路 GPIO5/4/37/45，20kHz，duty=0 |
| GPIO 是否连接外部电路 | 是，GPIO5/4/37/45 通过 C0→D0 连接到 PT2466 |
| 结果 | ADC 从 1913→574mV 跌落 |
| 结论 | **排除 LEDC timer 时钟域干扰假设**——MCPWM 完全独立时钟域，结果相同 |

## 4. 已确认事实总结

根据 Round 1-4 可以确认的因果链：

| 条件 | ADC GPIO1 读数 | 来源 |
|------|----------------|------|
| D0 在位 + 无任何 GPIO 输出配置 | ~1913mV 稳定 | Round 3 |
| D0 在位 + GPIO37/45 配为输出（连接 PT2466） | ~600mV 跌落 | Round 2 |
| D0 在位 + GPIO5/37/45 配为输出（连接 PT2466） | ~584mV 跌落 | Round 1 |
| D0 在位 + GPIO5/4/37/45 配为输出（连接 PT2466） | ~574mV 跌落 | Round 4 |

**关键观察**：
1. 触发条件 = "将 GPIO 配置为输出态"（与 PWM 外设类型、时钟源无关）
2. 所有触发实验中，被配置的 GPIO 都物理连接到 D0 板 PT2466 IN 引脚
3. 从未做过"GPIO 配置为输出但不连接外部电路"的对照实验
4. 万用表测 GPIO1 外部电压 0.8V 不变，说明分压网络本身输出无变化

## 5. 已排除的假设

| 假设 | 排除依据 | 来源 |
|------|----------|------|
| D0 板上电特性改变 ADC | 不配置 GPIO 时 ADC 稳定 | Round 3 |
| ADC1 内部通道串扰（GPIO4/5 占用 ADC1_CH3/CH4） | GPIO37/45 不在 ADC1 范围也触发跌落 | Round 2 |
| LEDC timer APB_CLK 时钟域干扰 ADC SAR | MCPWM 独立 PLL_F160M 时钟同样触发 | Round 4 |
| PWM 信号电磁干扰 | 所有 Round duty=0，GPIO 恒低电平 | Round 1-4 |

## 6. 未验证的假设（待 Round 5 决策）

当前核心未知：**"GPIO 配为输出导致 ADC 跌落"到底是 ESP32 芯片内部问题，还是因为输出 GPIO 连接到 D0 板外部电路引起的？**

### 假设 A：外部电路回灌干扰（可能性评估：高）

- 机理推测：GPIO5/4/37/45 配为输出低电平 → 驱动 PT2466 IN 引脚 → PT2466 进入 Coast 模式 → D0 板 DCDC/PT2466 内部偏置电流变化 → 通过共享 VDD33/GND/ADC 线回灌高频噪声到 ADC 高阻检测网络（110kΩ+15kΩ）
- 支撑依据：
  - 万用表带宽不足（~kHz），测不到高频噪声，所以显示 0.8V 不变
  - ADC SAR 采样带宽远高于万用表，会被高频噪声拉偏
  - 125kΩ 高阻检测网络（R12+R13）对噪声极其敏感
  - 所有触发实验都有外部电路连接这一共同条件
- 如果成立：解决方向是硬件滤波（GPIO1 对地加 100nF）或改版降低分压网络阻抗

### 假设 B：ESP32 GPIO 输出驱动器内部影响 ADC（可能性评估：低）

- 机理推测：GPIO5/4/37/45 pad 从高阻切换为推挽输出，输出驱动器电流通路改变芯片内部 VREF 或地电位
- 支撑依据：无直接证据，仅为理论可能性
- 反对依据：ESP32 大量应用中 GPIO 输出与 ADC 共存，未见普遍报告此问题
- 如果成立：需要软件规避（分时复用或补偿算法）

### 假设 C：VDD33 被拉低（可能性评估：低）

- 机理推测：PT2466 IN 引脚存在异常低阻抗路径，GPIO 输出时从 VDD33 拉出过大电流
- 反对依据：**万用表测 GPIO1 外部 0.8V 不变**；如果 VDD33 降低，分压输出应等比降低
- 除非万用表测量点和 ADC 读数不同步（可能性极低）
- 补充验证：可在 GPIO 输出后用万用表测 D0 板 VDD pin9 确认

### 假设 D：PT2466 工作态高频噪声通过连接器耦合（假设 A 的具体化）

- 与假设 A 本质相同，但指出具体耦合路径：U5 连接器 pin10(ADC) 与 pin6-8(GND)/pin9(VDD) 物理相邻
- 验证方法同假设 A

## 7. 下一步验证计划

### Round 5（决策分叉）：配置不连接外部电路的 GPIO 为输出

| 项目 | 内容 |
|------|------|
| 猜测 | 如果是 ESP32 内部问题（假设 B），任何 GPIO 配为输出都会导致 ADC 跌落；如果是外部电路问题（假设 A），只有连接到 D0 板的 GPIO 才会触发 |
| 操作 | 仅配置 GPIO21（摄像头引脚，当前无任何外部连接）为输出低电平，不操作电机 GPIO |
| GPIO 是否连接外部电路 | **否**，GPIO21 为摄像头 D0 引脚，当前无摄像头板接入 |
| 结果 | ADC 持续稳定 1911~1912mV，GPIO21 配为输出后完全无变化 |
| 结论 | **确认假设 A：问题是 D0 板外部电路导致，非 ESP32 芯片内部问题** |

## 8. Round 5b / Round 7：LEDC 启动 10s 后释放 + 万用表实测

| 项目 | 内容 |
|------|------|
| 目的 | 在 LEDC 运行期间和释放后分别用万用表实测 GPIO1 外部电压，确认 ADC 读数是否反映真实电压变化 |
| 操作 | Phase1: 完整 LEDC 20kHz 4ch (GPIO5/4/37/45) 初始化 duty=0（10s）；Phase2: 停止 LEDC + gpio_reset_pin(GPIO5/4/37/45) 恢复高阻 |
| 万用表测量 | Phase1 期间: 0.82V；Phase2 后: 3.3V；移除 D0 后: 3.3V→衰减至 0V |
| ADC 读数 | Phase1 期间: 未单独读（前几轮数据~574mV）；Phase2 后: 2500mV；移除 D0 后: 2500→2103→836→674→277→121→54→0mV |
| 补充观察 | 核心板+C0 无 D0：万用表瞬间~2V 后衰减至 0V（对应之前 ADC 不稳定现象） |

### 结论

**ADC 从未失准。** 它忠实反映了 GPIO1 外部真实电压变化。之前"万用表 0.8V 不变但 ADC 跌落"的前提是用不同固件时测量的，不能横向对比。

### Round 7 推翻的前提

| 之前认为 | 现在事实 |
|---------|---------|
| ADC 内部失准（外部不变但读数变） | **外部电压确实在变**，ADC 如实反映 |
| 分压网络输出恒为 0.8V | 0.8V 仅在电机 GPIO 输出低时的分压结果 |
| GPIO5/4/37/45 高阻时 ADC 节点 ≈ 分压值 0.4V | GPIO5/4/37/45 高阻 + D0 在位时实测 **3.3V**（≈VDD） |
| 问题是"ADC 被干扰" | 问题是"外部电路电压真的被改变了" |

### Round 7 建立的新事实

| 状态 | GPIO1 万用表实测 | ADC 读数 | 解释 |
|------|-----------------|---------|------|
| 核心板+C0（无 D0） | 瞬间~2V → 衰减至 0V | 不稳定/衰减 | ADC 节点无稳态驱动源，仅靠 1nF 电容暂存 |
| C0+D0 插入瞬间（GPIO5/4/37/45 高阻） | 来不及测 | **1911mV** | D0 刚接入但 GPIO5/4/37/45 未配置输出，ADC 节点由 D0 板驱动 |
| C0+D0 在位，LEDC 驱动低 | **0.82V** | ~574mV（前几轮数据） | GPIO LOW 通过 PT2466 形成分压，拉低 ADC 节点 |
| C0+D0 在位，GPIO5/4/37/45 释放回高阻 | **3.3V** | **2500mV** | ADC 节点恢复由 D0 板驱动到 VDD |
| D0 移除（C0 仍在） | 3.3V → 衰减至 0V | 2500→2103→836→674→277→121→54→0mV | D0 板驱动消失，电容缓慢放电 |

*注：1911mV vs 2500mV 差异待后续解释（可能是 Phase1 期间 ADC 校准/内部状态的影响，或是插入瞬间的暂态）

### 新问题：为什么 D0 在位时 ADC 节点是 3.3V？

设计文档标注的分压网络：VDD33 → 110kΩ → ADC 节点 → 15kΩ → GND，理论输出 ≈ 0.4V。

但实测 GPIO5/4/37/45 高阻时 ADC 节点 = 3.3V（≈VDD 直通），说明：
- 要么 110kΩ 电阻短路或未焊
- 要么 15kΩ 到 GND 的路径断开
- 要么 D0 板上存在另一条比 110kΩ 低得多的上拉路径直接连到 VDD
- 要么分压网络拓扑与文档标注不一致

**待确认：D0 板原理图上 ADC pin（U5 pin10）到 VDD33 之间的实际电阻路径。**

### 真实问题机理（修正版）

电机 GPIO 配置为推挽输出低电平后：
1. GPIO LOW → 经 C0 连接器 → D0 板 PT2466 IN 引脚
2. PT2466 IN 引脚到 ADC 节点之间（通过 D0 板内部布线/共享网络）形成了一条分压路径
3. 原本由 D0 VDD 驱动到 3.3V 的 ADC 节点被分压拉低到 0.82V
4. 这不是"干扰"，是**合法的电路分压行为**——只是设计时未预料到

## 9. 当前状态总结

1. **ADC 工作正常**——读数忠实反映外部电压
2. **真正的问题是硬件电路设计**——D0 板上 ADC 节点与电机 IN 引脚之间存在耦合路径
3. 需要确认 D0 板原理图，找到 ADC pin 实际连接拓扑
4. 之前所有"ADC 失准"的假设（A/B/C/D）全部作废——不存在失准问题

## 10. 待确认事项

### 基于原理图的可能性分析

D0 板 ADC 网络设计：
- R12 (110kΩ)：U5 pin10 (ADC) → VDD 网络
- R13 (15kΩ)：U5 pin10 (ADC) → GND
- 1nF 电容：ADC 节点对地（C0 板侧）
- 设计标注：`VADC = 15/(110+15)*3.3 = 0.4V`

PT2466 U3/U4 连接：
- IN1 (U5 pin1) → U3 pin6
- IN2 (U5 pin3) → U3 pin5
- IN3 (U5 pin5) → U4 pin6
- IN4 (U5 pin7) → U4 pin5
- **IN1-IN4 与 ADC (U5 pin10) 在原理图上无直接电阻/电容连接**

VDD 网络来源：
- 设计意图：ETA8120S2G DCDC 输出 5.0V
- 实际推测：DCDC 可能未工作（无 VBAT），VDD 由 C0 板通过 U5 pin9 供给 3.3V

#### 可能性 1：R13 (15kΩ) 开路（未焊/虚焊/损坏）— ❌ 已排除

- **实测**：R13 在板阻值 ≈ 14kΩ（标称 15kΩ，正常）
- 结论：R13 元件本身完好且已焊接

#### 可能性 2：R13 GND 端虚焊（PCB via 断裂或焊盘脱落）— ⚠️ 待运行态验证

- 冷态 R13=14kΩ 证明元件和焊点有通路
- 但不排除运行态条件性失效（热膨胀/应力导致 via 微断）
- **待验证**：Round 7 Phase2 状态下量 R13 两端压差（见 Round 8 计划）

#### 可能性 3：DCDC 未工作，VDD 由 C0 板供 3.3V — 可能但非根因

- ETA8120S2G EN (pin4) 未使能 → DCDC 不输出
- VDD 网络实际由 C0 板通过 U5 pin9 供 3.3V
- 如果 R13 正常(已确认 14kΩ)，分压 = `14/(R12+14)*VDD`
- **与 R12 实测结合**：在板测 R12≈45kΩ（标称 110kΩ），但在板并联了 PT2466 VCC 通路（R8/R9=10kΩ 到 VDD），实际 R12 大概率仍为 110kΩ
- 验证方法：量 ETA8120S2G 输出端 (VDD) 实际电压

#### 可能性 4：R12 (110kΩ) 实际值异常 — ⚠️ 需离板确认

- **在板实测**：R12 ≈ 45kΩ（标称 110kΩ）
- 在板解读：VDD 网络有 PT2466 VCC (通过 R8=10kΩ/R9=10kΩ)、nSLEEP 上拉等并联路径到 VDD，使得从 R12 高端看到的等效阻抗远低于 110kΩ
- **R12 实际值 110kΩ 的验证**：如果 R12=110kΩ 且 R13=14kΩ，分压 = `14/(110+14)*3.3 = 0.37V` → 和"GPIO5/4/37/45 高阻时 ADC=3.3V"严重矛盾
- **如果 R12 真的是 45kΩ 且 R13=14kΩ**：分压 = `14/(45+14)*3.3 = 0.78V` → 和 Phase1 实测 0.82V 吻合！但仍然无法解释高阻时 3.3V
- **核心矛盾**：无论 R12=110kΩ 还是 45kΩ，只要 R13=14kΩ 正常通 GND，高阻时 ADC 就不可能是 3.3V
- 验证方法：离板测 R12 确认真实阻值

#### 可能性 5（低）：U5 连接器 pin 间焊桥或 PCB 漏电

- U5 pin7 (IN4/GPIO45) 与 pin9 (VDD) 或 pin10 (ADC) 物理相邻
- 如果有焊桥，IN4 状态会直接影响 ADC 节点
- 但无法解释"GPIO5/4/37/45 均高阻时 ADC=3.3V"
- 验证方法：显微镜检查 U5 焊点

#### 新增可能性 6（高）：R13 运行态条件性失效或 GND 路径通断受控

- **核心矛盾**：R13 冷态测量 14kΩ 正常，但上电运行时 GPIO5/4/37/45 高阻→ADC=3.3V（=VDD），说明 R13 到 GND 的 14kΩ 路径在该状态下等效消失
- 可能机制：
  - R13 GND via 在温升/机械应力下微断（概率低，冷态已通）
  - R13 的 GND 并非真正板地，而是经过某个开关/MOSFET 控到 GND（需查 PCB 布局确认 R13 GND 端连接）
  - **最可能**：PT2466 nSLEEP=HIGH 时某个内部路径给 ADC 节点提供了远低于 R12 的上拉（覆盖分压效果），使 ADC 被钳到 VDD 附近
- **验证方法（Round 8）**：Phase2 状态下量 R13 两端各对 GND 的电压

### 0.82V 机理（基于 R13 GND 断开的解释）

R13 GND 断开 → ADC 节点平时 = VDD (3.3V)。当 GPIO5/4/37/45 推挽输出 LOW 时 ADC 跌到 0.82V 的通路：

- IN1-IN4 与 ADC 在原理图上无直连
- **最可能机理**：GPIO5/4/37/45 输出 LOW → PT2466 进入工作态 → VCC (pin8) 通过 R8/R9 (10kΩ) 从 VDD 网络取电 → VDD 网络电压被负载拉低
- 如果 VDD 从 3.3V 跌到 0.82V（因为 C0 板驱动能力有限，长走线+连接器阻抗），ADC 节点 = VDD = 0.82V
- 验证：Phase1（GPIO5/4/37/45 输出 LOW）时量 VDD (U5 pin9) 对 GND 电压是否也 ≈0.82V

## 11. 2026-07-24 硬件闭环与正式实现

### 已确认硬件结论

- 原电压波动原因：检测脚没有固定电平，浮空导致波动。
- C0板在ADC节点新增20kΩ上拉到3.3V，硬件改动后电平可以稳定。
- D0板R12上拉已移除，R13保持15kΩ下拉。
- 核心板+C0：外部测试点稳定为 3.3V；旧调试固件曾显示 2500mV，正式固件改为`raw=4095`、`cal_mv=3160`并明确标记饱和。
- 核心板+C0+D0：外部测试点稳定为 1.45V；旧调试固件曾显示 1029~1030mV，正式固件实测校准值为`1435~1437mV`。
- 核心板ADC引脚与D0 ADC引脚均实测1.45V，没有可见接插件压降，不在公式中引入接触电阻。
- 名义分压为 `3.3V * 15kΩ / (20kΩ + 15kΩ) = 1.414V`；1.45V作为当前实测标定中心，差异归入电阻、供电和测量误差，不能由单点唯一反推某只电阻误差。

### 3.3V 显示 2500mV 的软件与 ADC 原因

旧 `slot_expansion_c0.c` 使用：

```c
readings[i] = raw * 2500 / 4095;
```

- 该公式把任意 12bit 满量程 raw=4095 固定标成 2500mV，输出不可能超过 2500mV。
- 静态计算确认 raw=4094 只会显示 2499mV；实板稳定显示恰好 2500mV，说明本轮中位 raw 已达到 4095。
- 当前实际通道配置是 `ADC_ATTEN_DB_12`（约 11dB）和 `ADC_BITWIDTH_DEFAULT`。ESP-IDF v5.5.4 的 ESP32-S3 HAL 说明：该档理论 full-scale 为 3.9V，但最大输入受 `VDD_A` 限制；最准确的推荐输入范围约为 150~2450mV。
- 因此 3.3V 直接输入 ADC 引脚没有超过 3.3V 引脚边界，但超出了推荐精确测量范围；本板 raw=4095 又确认该点已经饱和。当前 2500mV 同时是“ADC 高端饱和”和“软件错误标尺封顶”的结果。
- 直接把公式中的 2500 改成 3300 只能让 raw=4095 显示为 3300mV，不能证明或恢复准确测量。若只做板卡分类，可将高 raw 定义为“高电平/饱和档”；若需要准确测量 3.3V，必须先通过硬件分压让 ADC 引脚电压落入约 2450mV 以内，再用 ESP-IDF ADC calibration API 和实际分压阻值换算。

### 正式源码处理

- 旧 `raw * 2500 / 4095` 公式已删除。当前每轮采集5次raw、取中位raw，并用ESP-IDF curve fitting calibration换算ADC引脚电压。
- `raw>=4000` 作为C0单独在位的高端饱和档；日志必须标出saturated，不能把它描述成精确3.3V测量。
- C0+D0初始校准窗口采用1200~1700mV，覆盖1.45V实测中心；校准不可用时采用raw 1400~2200后备窗口。
- 低档边界采用校准电压<=800mV或raw<=1200；当前正式验收拓扑从核心板+C0开始，单核心板样本仅作为后续扩展数据，不阻塞当前Demo验收。
- 中间未命中窗口的值归为UNKNOWN，不累计插入或拔出消抖，避免过渡电平误触发。
- Round 7的“LEDC运行10秒后停止、释放GPIO并锁存ready”是历史排查手段，正式源码已删除。当前Demo只在应用入口等待10秒以抓取日志；D0插入后持续100%前进，拔出后stop并deinit。
